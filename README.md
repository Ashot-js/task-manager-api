# Task Manager API

REST API for personal task management: JWT authentication, user/admin roles, CRUD,
filtering, search, sorting, pagination, interactive OpenAPI docs, Jest tests and Docker.

**Try it:** https://task-manager-api.onrender.com/docs — register, press **Authorize**, paste the token,
then call the task endpoints. (Free hosting: the first request after a pause takes up to a minute.)

## Stack

Node.js · TypeScript · Express 5 · PostgreSQL (`pg`) · Zod · JWT · bcrypt · helmet · Swagger UI ·
Jest + Supertest · Docker · GitHub Actions

## Endpoints

| Method | Path | Who | What |
|--------|------|-----|------|
| POST | `/auth/register` | anyone | create an account, returns a token |
| POST | `/auth/login` | anyone | get a token |
| GET | `/auth/me` | user | current user |
| GET | `/tasks` | user | own tasks (admin: all) — `status`, `priority`, `q`, `due_before`, `due_after`, `sort`, `order`, `page`, `limit`, `owner_id` (admin) |
| POST | `/tasks` | user | create |
| GET / PATCH / DELETE | `/tasks/:id` | owner or admin | read, partial update, delete |
| GET | `/users` | admin | users with task counts |
| PATCH | `/users/:id/role` | admin | make user/admin |
| DELETE | `/users/:id` | admin | delete a user and their tasks |
| GET | `/health` | anyone | liveness + database check |

Errors always look like `{ "error": { "code", "message", "details"? } }`.

## Design notes

- **Access control in SQL:** every task query carries `owner_id = $user` unless the caller is an admin,
  so another user's task is simply "not found" (404), never leaked.
- **Roles are read from the database on each request** — demoting or deleting a user takes effect
  immediately, not when their 7-day token expires.
- **Safe dynamic queries:** filters are parameters; sort columns and updatable fields come from whitelists.
  `%` and `_` in searches are matched literally.
- **Stable pagination:** `id` breaks ties in every sort, so pages never overlap.
- The schema is created on start (`db/schema.sql`, idempotent) inside `DB_SCHEMA`, so the API can share
  a database with other apps. RLS is enabled to keep hosted Postgres' public REST endpoints out.

## Run

```bash
docker compose up --build           # API + Postgres → http://localhost:3000/docs
```

or with your own Postgres:

```bash
cp .env.example .env                # DATABASE_URL, JWT_SECRET
npm install
npm run dev
npm run make-admin -- you@example.com
```

## Test

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/tasks npm test   # 24 tests, real Postgres
```

Tests recreate their own `api_test` schema. GitHub Actions runs them on every push.

## Deploy (free)

`render.yaml` describes the Render web service. Set `DATABASE_URL` (e.g. Supabase → Connect → Session pooler);
`JWT_SECRET` is generated by Render; tables go to the `taskapi` schema.
